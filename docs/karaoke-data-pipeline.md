# カラオケデータ生成パイプライン

## 目的

管理者が所有する4種類の素材から、スマートフォンアプリで再生・歌詞表示・採点に利用するカラオケデータを生成する。

## 入力

1. 元音源 WAV または MP3
2. カラオケ音源 WAV または MP3
3. アカペラ音源 WAV または MP3
4. 歌詞 TXT

音源は3種類ごとにWAVとMP3を混在可能とする。入力ファイルは上書きせず、ハッシュ値、MIMEタイプ、コーデック、ビットレート、サンプルレート、チャンネル数、ビット深度、再生時間とともに保存する。

## 管理画面のワークフロー

1. 楽曲の基本情報を入力する。
2. 4素材をアップロードする。
3. 自動検査を実行する。
4. Pythonワーカーへ解析ジョブを投入する。
5. 解析結果をタイムラインエディターでプレビュー・修正する。
6. 検証に合格したバージョンを公開する。

公開済みデータは直接更新せず、新しいバージョンとして生成する。処理状態は `draft`、`uploaded`、`analyzing`、`review_required`、`ready`、`published`、`failed` で管理する。

## 解析処理

### 1. 音源検査・正規化

- `ffprobe`で実際のコンテナ、コーデック、再生時間、サンプルレート、チャンネル数を取得する。
- FFmpegのデコード結果を使い、破損、無音、クリッピングを検査する。
- 3音源の長さと開始位置の差を測定する。
- `ffmpeg`で解析用コピーをPCM WAV、48 kHz、モノラルへ変換する。
- アライメント、ピッチ抽出、波形生成は解析用WAVを使用し、MP3の圧縮差やデコーダー差を後続処理へ持ち込まない。
- 元ファイルは変更しない。

変換例:

```bash
ffmpeg -nostdin -hide_banner -i input.mp3 -vn -map_metadata -1 -ac 1 -ar 48000 -c:a pcm_s16le analysis.wav
```

実装ではシェル文字列を組み立てず、Pythonの`subprocess`へ引数配列として渡す。タイムアウト、終了コード、標準エラーをジョブログへ記録する。

### 2. 歌詞の正規化

- BOM、改行コード、空行、全角・半角記号を正規化する。
- セクション、歌詞行、読み、表示文字列を分離する。
- Geminiには歌詞の誤字候補、繰り返し、英数字の読み、区間候補を構造化JSONで生成させる。
- AIによる変更候補は原文と差分表示し、無条件で確定しない。

### 3. 歌詞アライメント

- アカペラ音源と既知の歌詞を強制アライメントし、行・単語・音素の開始終了時刻を生成する。
- 音声認識結果だけを正解にせず、入力歌詞を基準に対応付ける。
- Geminiのタイムスタンプ付き解析は初期区間推定と低信頼区間の再確認に使用する。
- 各区間に信頼度を保存し、閾値未満を管理画面で警告する。

### 4. 採点用基準データ

- アカペラ音源から基本周波数、音量、発声区間をフレーム単位で抽出する。
- 無声区間と不確実な周波数は採点対象外としてマークする。
- 歌詞タイムラインと結合し、フレーズ単位の基準ピッチ系列を生成する。
- 採点ロジックの変更に備え、解析アルゴリズムとモデルのバージョンを保存する。

### 5. 配信用データ

- カラオケ音源からFFmpegでアプリ配信用ファイルを生成する。初期版は互換性を優先してAAC/M4Aを標準とし、必要に応じてMP3も生成可能にする。
- 音量正規化はEBU R128に基づくFFmpegの`loudnorm`を2パスで実行し、測定結果をメタデータとして保存する。
- 行・単語単位の歌詞タイムラインJSONを生成する。
- 採点用基準データはアプリへ全量配布せず、原則としてサーバー側で利用する。
- 元音源とアカペラ音源は管理・解析用途とし、アプリから直接取得できないようにする。

## 管理画面に必要な機能

- ドラッグ＆ドロップ式の4素材アップロード
- WAV／MP3形式表示とFFmpeg変換結果の確認
- アップロード進捗、解析進捗、エラー詳細
- 音源波形と同期した歌詞タイムライン
- 行・単語の開始終了時刻の編集
- 再解析、差分確認、バージョン履歴、公開・公開停止
- 低信頼区間、音源ずれ、クリッピング、欠落歌詞の警告
- 元音源／カラオケ／アカペラの切り替え試聴

## 主なデータモデル

- `songs`: 楽曲情報
- `song_assets`: 入力・生成ファイルとメタデータ
- `processing_jobs`: 非同期処理の状態、進捗、エラー
- `lyric_versions`: 歌詞原文と正規化バージョン
- `lyric_segments`: 行・単語・音素タイムライン
- `pitch_references`: 採点用基準データ
- `karaoke_releases`: 公開バージョン

SQLiteではワーカーを単一プロセスまたは低並列で動かし、ジョブ取得時の短いトランザクションとタイムアウトを設定する。利用量が増えた段階でPostgreSQLと専用ジョブキューへ移行できるよう、DB固有処理を分離する。

## セキュリティ

- 音源アップロードと公開操作は管理者に限定する。
- 拡張子やブラウザー申告のMIMEタイプを信用せず、`ffprobe`で実データの形式、コーデック、サイズ、再生時間を検証する。
- FFmpegにはネットワーク入力を渡さず、アップロード済みの隔離ファイルだけを処理する。
- ファイル名を内部IDへ置き換え、非公開素材は署名付きURLまたはAPI経由で扱う。
- Geminiなど外部サービスへ送信する素材と解析ログを監査可能にする。
- APIキーをDBやソースコードへ保存しない。
